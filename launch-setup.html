Public beta launch setup

The local app is for testing. Complete these steps before inviting the public. Never paste passwords or secret keys into chat or website files.

  1. Activate the latest community features

    In the existing Supabase project, open SQL Editor and run the saved engagement-upgrade.sql migration once. Then run test-engagement-security.sql, which rolls back all test records. Reload the app after successful execution. Do not rerun schema.sql or earlier migrations.

  2. Choose hosting

    Deploy the FictionCom folder to a Node 22+ or Docker host with HTTPS. Use the supplied Dockerfile or run node serve.mjs with HOST=0.0.0.0 and the assigned PORT. Configure /healthz as the health check. A static-only host cannot run catalog search. A hosting provider’s subdomain is enough to begin.

  3. Configure signup emails

    Create an SMTP email-sending account and verify a sender/domain. Configure SPF/DKIM, then enter its SMTP credentials privately in Supabase. Keep email confirmation enabled. Test signup, resend and password recovery with two independent email addresses.

    Official SMTP setup

  4. Enable Google and Microsoft login

    Create the provider applications and privately configure their credentials in Supabase. Register the callback shown by Supabase, plus your production origin where required. Test each provider with two accounts before enabling its OAUTH_READY flag in config.js. The buttons stay disabled until then.

    Google setup · Microsoft setup

  5. Set production redirects and public contact details

    Set the real HTTPS Site URL and exact allowed confirmation/reset redirects in Supabase. Fill the operator identity and support contact in the Privacy and Terms pages. Minimum age is 14.

  6. Run independent-account and real-phone tests

    Test iPhone/Safari and Android/Chrome: photo selection, video playback, uploads on a slow connection, draft recovery, story navigation, long posts and replies. With two accounts verify private follow approval, blocked users, username uniqueness, spoiler progress, notifications and story reply permissions. Confirm guests can browse but cannot post or interact.

  7. Prepare ongoing operation

    Configure storage cleanup, usage alerts and backups. Perform a restore rehearsal. Keep the moderator available for reports and support. AI review remains disabled.

Hosting, SMTP, provider applications, production contact details and real-device checks are pending until the owner supplies or completes them.
